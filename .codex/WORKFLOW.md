# Agent Workflow

Этот каталог хранит постоянные роли агентов для проекта `proletarka`.

Цель:

- быстро восстанавливать рабочие роли между сессиями;
- не держать правила агентов только в чате;
- использовать единый проектный контекст при новых задачах.

## Базовые правила

Перед созданием любого агента:

1. Прочитать `/home/tuor4eg/pets/proletarka/PROJECT_CONTEXT.md`.
2. Прочитать нужную роль в `/home/tuor4eg/pets/proletarka/.codex/agents/`.
3. Использовать агента только для чёткой и ограниченной подзадачи.
4. После результата сверить вывод с контекстом проекта.

## Рекомендуемые роли

- `architect.md` — хранитель проектной рамки и архитектурной простоты.
- `reviewer.md` — reviewer для проверки рисков, регрессий и пробелов в тестировании.

## Когда использовать архитектора

Подключать перед:

- новой крупной фичей;
- изменением схемы БД;
- добавлением новой сущности;
- крупным рефакторингом;
- выбором между несколькими вариантами реализации.

Просить у него:

- краткую рамку задачи;
- оценку соответствия духу проекта;
- проверку на переусложнение;
- короткую пост-проверку после реализации.

## Когда использовать reviewer

Подключать:

- после заметных изменений в логике;
- перед финальной сдачей задачи;
- когда есть риск регрессий;
- когда нужна независимая проверка решений.

Просить у него:

- список находок по важности;
- подозрительные места в логике;
- пропущенные тесты и сценарии;
- остаточные риски.

## Стартовая фраза для новой сессии

Можно использовать такую команду:

`Сверься с PROJECT_CONTEXT.md и .codex/WORKFLOW.md, потом подними архитектора по .codex/agents/architect.md.`
